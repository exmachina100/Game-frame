# ioquake3 camera pilot — first native scene positioning

This milestone builds on a **verified Windows installation of Quake III Arena launched by GameFrame**. It targets actual 3D camera positioning rather than the Pong emulator. It is a console-based feasibility pilot, **not yet an autonomous GameFrame camera bridge**.

## Existing Windows paths

- Python project: `D:\AI\Game Frame\Game-frame`
- ioquake3: `D:\AI\Game Frame\ioquake3\ioquake3.x86_64.exe`
- Existing game data: `D:\AI\Quake 3 Arena\baseq3`
- Config export folder: `D:\AI\Game Frame\ioquake3\baseq3` (created by test generator)

Game data stays in its current folder. No .pk3 archives should be committed to GitHub.

## Experiment A — load level, fly, take screenshots and record demo

From PowerShell:

```powershell
cd "D:\AI\Game Frame\Game-frame"
git pull origin main
python -m unittest discover -s tests -v
python -m gameframe.ioquake3_camera_test
python -m gameframe.ioquake3_camera_test --write
python -m gameframe.ioquake3_launcher --launch
```

In the launched Quake III console (usually `~`):

```
/exec gameframe_camera_test.cfg
```

This loads a local `devmap q3dm1` session. If the map doesn't change, enter `/devmap q3dm1` manually. Use standard WASD + mouse to move; **F6** toggles cheat-enabled `noclip`; **F7** requests a native JPEG screenshot; **F8** starts a native engine demo; **F9** stops it. Depending on game menus/bind behavior, commands may need to be entered in the console manually instead.

The generated cfg deliberately requires you to execute it yourself. Outputs are generated by ioquake3 in its configured home paths. The demo is a **game demo**, not automatically an AVI/MP4 film.

## Experiment B — scripted static camera placement (experimental)

We can compile the generic `gameframe.cinematic.v1` camera commands to Quake III's developer-console `setviewpos x y z yaw` command. This built-in command generally requires a local cheat-enabled map (`devmap`). It teleports the **player view**, not a true detached cinematic camera, and pitch/roll and timed interpolation are not yet implemented. Availability and behavior must be verified on your specific build.

```powershell
python -m gameframe.ioquake3_camera_takes docs/examples/quake_camera_pilot.json
python -m gameframe.ioquake3_camera_takes docs/examples/quake_camera_pilot.json --write
```

With the game running a `devmap` session, type in Quake III console:

```
/exec gameframe_take_01.cfg
/exec gameframe_take_02.cfg
/exec gameframe_take_03.cfg
```

Each command **manually** sets an example position and yaw. These positions are placeholders and may be inside level geometry; collision and camera clearance are not yet validated. Look for a change in viewpoint and tell us if the game reports `Unknown command 'setviewpos'`, `Cheats are not enabled`, or another message.

The original `docs/examples/alley_scene.json` contains actor and camera actions **not** supported by this console pilot. Don't use it for the cfg exporter.
